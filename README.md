# یابنده — پروژهٔ قابل‌استقرار

یابنده یک سامانهٔ فارسی برای ثبت و جست‌وجوی وسایل گم‌شده و پیدا‌شده است. این بسته شامل برنامهٔ Flask، پایگاه دادهٔ SQLite، بارگذاری عکس، ورود امن، تطبیق آگهی‌ها، تست‌ها و فایل‌های اجرای میزبان است.

## محتویات

- مرور عمومی آگهی‌ها، جست‌وجو و فیلتر بر اساس وضعیت و نوع وسیله
- ثبت‌نام و ورود؛ رمزها فقط به‌شکل هش‌شده ذخیره می‌شوند
- ثبت و حذف آگهی توسط صاحب همان آگهی
- نمایش ایمیل تماس فقط برای کاربران واردشده
- هشت آگهی نمونه با برچسب روشن «نمونه نمایشی»؛ این آگهی‌ها گزارش واقعی نیستند و اطلاعات تماس ندارند
- تطبیق آگهی‌های گم‌شده و پیدا‌شده بر پایهٔ نوع، نام، رنگ، محل و توضیحات
- ایمیل اختیاری برای گزارش‌دهندهٔ وسیلهٔ گم‌شده

امتیاز تطبیق از نام (۴۰٪)، رنگ (۲۰٪)، محل (۲۰٪) و توضیحات (۲۰٪) ساخته می‌شود. دستهٔ وسیله نیز باید شباهت بالایی داشته باشد؛ امتیاز کلی باید دست‌کم ۰٫۵۰ باشد و نام یا هم‌زمان رنگ و محل شواهد کافی بدهند. پیش از مقایسه، شکل‌های رایج حروف فارسی و عربی یکسان‌سازی می‌شوند. این روش ساده و قابل توضیح است، نه تشخیص قطعی مالکیت.

## اجرای محلی

به Python 3.11 یا جدیدتر نیاز دارید. فایل ZIP را استخراج کنید و ترمینال را در همان پوشه‌ای باز کنید که `app.py` و `wsgi.py` در آن قرار دارند.

```bash
python -m venv .venv
```

فعال‌سازی محیط مجازی:

```bash
# ویندوز
.venv\Scripts\activate

# لینوکس یا macOS
source .venv/bin/activate
```

نصب وابستگی‌ها:

```bash
python -m pip install -r requirements.txt
```

فایل `.env.example` را به `.env` کپی کنید. مقدار `SECRET_KEY` را با یک مقدار تصادفی و طولانی جایگزین کنید. برای ساخت مقدار تصادفی می‌توانید اجرا کنید:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

در PowerShell:

```powershell
Copy-Item .env.example .env
```

در لینوکس یا macOS:

```bash
cp .env.example .env
```

برنامه به‌صورت خودکار جدول‌های پایگاه داده را می‌سازد. دستور اختیاری آماده‌سازی دستی:

```bash
flask --app app init-db
```

اجرای محلی:

```bash
python app.py
```

برنامه روی `http://127.0.0.1:5000` باز می‌شود. در محیط اجرا روی `0.0.0.0` و پورتی که میزبان در متغیر `PORT` می‌دهد گوش می‌دهد؛ مقدار محلی پیش‌فرض `5000` است.

## متغیرهای محیطی

| نام | کاربرد |
| --- | --- |
| `APP_ENV` | برای استقرار روی `production` بگذارید؛ در تولید `SECRET_KEY` اجباری است. |
| `SECRET_KEY` | کلید تصادفی و محرمانه برای نشست‌ها و محافظت فرم‌ها؛ در کد یا فایل ZIP مقدار واقعی قرار ندهید. |
| `PORT` | پورتی که میزبان تعیین می‌کند؛ در اجرای محلی پیش‌فرض `5000` است. |
| `DATABASE_PATH` | مسیر فایل SQLite؛ پیش‌فرض `instance/yabande.sqlite3` است. |
| `UPLOAD_DIR` | پوشهٔ عکس‌ها؛ پیش‌فرض `static/uploads` است. |
| `PUBLIC_BASE_URL` | نشانی عمومی سایت، بدون `/` پایانی؛ برای ساخت پیوند ایمیل پشت میزبان‌های واسط مفید است. |
| `SMTP_HOST` | نشانی سرور ایمیل؛ برای Gmail مقدار `smtp.gmail.com`. |
| `SMTP_PORT` | درگاه SMTP؛ معمولاً `587` و برای اتصال امن مستقیم `465`. |
| `SMTP_USER` | نشانی Gmail که برای احراز هویت استفاده می‌شود. |
| `SMTP_PASSWORD` | App Password گوگل؛ فقط در بخش امن متغیرهای میزبان قرار دهید. |
| `MAIL_FROM` | نشانی فرستنده؛ اگر خالی باشد از `SMTP_USER` استفاده می‌شود. |

اگر اطلاعات SMTP کامل نباشد، ثبت و جست‌وجوی آگهی همچنان کار می‌کند و برنامه پیام تشخیصی امنی در گزارش اجرا ثبت می‌کند. وضعیت «ارسال‌شده» فقط پس از پاسخ موفق SMTP ذخیره می‌شود. هر زوج آگهی گم‌شده/پیدا‌شده فقط یک بار برای ارسال ثبت می‌شود؛ SMTP تضمین تحویل به صندوق ورودی نمی‌دهد.

### ساخت App Password برای Gmail

1. در حساب Google احراز هویت دومرحله‌ای را فعال کنید.
2. از تنظیمات امنیت حساب، یک App Password مخصوص برنامه بسازید؛ اگر این گزینه برای حساب شما فعال است.
3. مقدار آن را فقط در بخش Environment Variables یا Secrets میزبان به‌عنوان `SMTP_PASSWORD` ذخیره کنید. رمز اصلی Gmail را استفاده نکنید.
4. `SMTP_HOST`، `SMTP_PORT`، `SMTP_USER` و `MAIL_FROM` را نیز تنظیم و برنامه را دوباره اجرا کنید.
5. با دو حساب دارای ایمیل واقعی، یک آگهی گم‌شده و یک آگهی پیدا‌شدهٔ مشابه ثبت کنید؛ سپس صندوق ورودی و هرزنامه را بررسی کنید.

ارسال واقعی ایمیل در این بسته از این محیط آزمایش نشده است؛ برای اطمینان، آن را در میزبان خود با حساب‌های آزمایشی امتحان کنید.

## استقرار روی میزبان Python/Flask

1. ZIP را استخراج یا محتوای آن را در ریشهٔ برنامهٔ میزبان بارگذاری کنید؛ `app.py`، `wsgi.py` و `requirements.txt` باید در ریشه باشند.
2. Python 3.11 یا جدیدتر را انتخاب کنید و وابستگی‌ها را با `python -m pip install -r requirements.txt` نصب کنید.
3. متغیرهای محیطی محرمانه را در پنل میزبان تنظیم کنید. `APP_ENV=production` و یک `SECRET_KEY` تصادفی و محرمانه ضروری هستند. فایل `.env.example` حاوی مقدار واقعی نیست.
4. فرمان اجرای عمومی با Gunicorn:

```bash
PORT="${PORT:-5000}"
gunicorn --workers 2 --bind "0.0.0.0:${PORT}" wsgi:app
```

   اگر میزبان از `Procfile` پشتیبانی کند، فرمان از همان فایل خوانده می‌شود. اگر متغیر `PORT` را به فرایند ندهد، از فرمان متناسب با میزبان برای درگاه خودش استفاده کنید.
5. پس از استقرار، مسیر `/health` باید پاسخ JSON با وضعیت `ok` بدهد. مسیر `/` برای کاربر واردنشده به صفحهٔ ورود می‌رود و `/browse` آگهی‌های عمومی را نشان می‌دهد.

## پایگاه داده و فضای پایدار

SQLite و عکس‌ها به‌طور پیش‌فرض روی دیسک محلی برنامه ذخیره می‌شوند. میزبان‌هایی که دیسک موقت دارند ممکن است فایل‌ها را هنگام راه‌اندازی مجدد، استقرار نسخهٔ جدید یا توقف نمونه پاک کنند. در این حالت، یک دیسک پایدار/Volume بسازید، آن را به برنامه متصل کنید و مسیرهای مطلق آن را تنظیم کنید؛ برای نمونه:

```text
DATABASE_PATH=/مسیر/دیسک-پایدار/yabande.sqlite3
UPLOAD_DIR=/مسیر/دیسک-پایدار/uploads
```

هم پایگاه داده و هم پوشهٔ عکس باید پایدار باشند؛ پشتیبان‌گیری منظم از هر دو لازم است. هنگام انتقال به میزبان دیگر، فایل SQLite و پوشهٔ عکس را نیز منتقل کنید. SQLite برای یک نمونهٔ برنامه مناسب است؛ اگر چند نمونهٔ هم‌زمان یا مقیاس‌پذیری چندسروری لازم دارید، پایگاه دادهٔ مدیریت‌شدهٔ میزبان را انتخاب کنید و برای مهاجرت از SQLite برنامه‌ریزی جداگانه انجام دهید.

برنامه جدول‌ها را در شروع می‌سازد و هشت آگهی نمایشی را فقط یک‌بار، آن هم وقتی پایگاه داده خالی باشد، اضافه می‌کند. داده‌های موجود پاک یا جایگزین نمی‌شوند. آگهی نمونه اطلاعات تماس ندارد و از تطبیق و اعلان ایمیل کنار گذاشته می‌شود.

## تست و بررسی

```bash
python -m compileall -q app.py wsgi.py tests
python -m unittest discover -s tests -v
```

وابستگی‌ها را می‌توان با `python -m pip check` بررسی کرد. تست‌ها شامل مسیرها، ورود و ثبت‌نام، محافظت CSRF، دسترسی‌ها، ساخت و جست‌وجوی آگهی، حفظ داده هنگام راه‌اندازی مجدد، اعتبار عکس، الگوریتم تطبیق و رفتار ایمیل با SMTP ساختگی هستند.
